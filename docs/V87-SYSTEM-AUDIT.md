## 資料庫與安全注意事項

1. 現有遷移檔 `0000`–`0016`，涵蓋身分、運動回覆、廣場、私人島、造型、故事、小屋、收藏、家具實例及環境。不存在通用貨幣、背包、種植或多人 Session 表。
2. `0016_cabin_environment.sql` 已在來源，但 `drizzle/meta/_journal.json` 只索引到 0015。隔離測試按檔名套用所有 SQL；這不證明正式部署遷移機制會處理 0016。V87 新遷移前應核對平台遷移契約及實際 schema，不憑測試成功推論正式資料庫完整。
3. 目前故事以伺服器檢查預期 step/path、條件更新及唯一鍵防重；家具依完成故事推導解鎖。擴充時保留原授權，不能將任務重置或重發既有獎品。
4. 新 Quest Engine 只接受由伺服器成功完成的場景動作事件；必須驗證身分、目標、允許動作、事件時段及進度，不能接受任意 event/reward/currency/item 數量。網頁場景本身不能證明實體遊玩，需明確定義伺服器可驗證的互動。
5. 正式資料未下載／修改。隔離測試驗證的是合成舊玩家資料保存，不是正式帳號逐筆稽核。
