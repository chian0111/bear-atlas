## Model contract: bear-sim-1

Base: Monday 2026-11-09 00:00 Asia/Taipei (2026-11-08T16:00Z), index100. This is a constructed simulation baseline, not observed player data. Periods are seven days, change Monday00:00 Taiwan time. Base period has no weekly comparator. Current period is a complete scenario snapshot, not an observed partial-week statistic. Rounding: raw prices and index outputs four decimal places, UI two decimals; underlying model inputs retained.

| Good | Base price (simulated coins/unit) | Fixed basket units | Base supply = demand (units/week) |
|---|---:|---:|---:|
| Carrot | 10 | 8 | 100 |
| Pumpkin | 20 | 3 | 60 |
| Coffee | 30 | 4 | 80 |
| Fish | 25 | 3 | 70 |
| Wood | 15 | 4 | 50 |
| Basic furniture materials | 40 | 2 | 40 |

Basket base cost475. Price = base price × clamp(sqrt((demand/baseDemand)/(supply/baseSupply)),0.5,2). All six base supply/demand pairs are equal. Matched quantity = min(supply,demand). A deliberately simple static learning model, not a dynamic equilibrium forecast.

BBI =100×(40%×sum matched units/400 +25%×sum supply units/400 +20%×coffee matched units/80 +15%×sum(basePrice×matched units)/8700). Components are overlapping volume indicators, not GDP or a ledger sum. Base prices are held fixed in the consumption proxy, so inflation alone is not real activity. Every period stores raw components, contributions, event ID, status/source/version and SHA-256 digest. No player login or asset information enters this calculation.

BCPI =100×sum(current price×fixed basket quantity)/475. Base change=(index/100−1)×100%; weekly change=(current/prior−1)×100%. Annual comparator requires a full calendar year since baseline; uses last weekly period on/before the same date last year. At launch annual change is null and UI explicitly says insufficient12months. Even future annual output remains labelled simulation, never actual observed inflation.

## Event cycle / termination

Base period0 stable. Starting period1: harvest (carrot supply+40%, demand unchanged), festival (coffee supply+20%, demand+40%), building (wood demand+30%, supply unchanged), stable; repeat four-period pattern. Each event has unique version:period:kind ID and exclusive end timestamp. Next period always recalculates from base, never compounds. Weekly explanation states both new event starts and prior event ends; stored history permits direct comparison. Stable weeks can change relative to previous shocked week.

Lab uses the same market/indices functions, separate server-side URL-enum selection (three events, standard or2× incremental shock, reset). It never saves lab results into official tables. Query values cannot set a price/index, choose official period, write assets or alter global events. This release has no financial write endpoint.
