# V100 — character life, styles, fireworks and furnishings

- Shop adds three outfits (sage knit 22, lilac apron 24, ocean hoodie 26), three accessories (straw hat 14, berry scarf 12, star explorer bag 16), and an 8-coin virtual fireworks ticket. Existing server-owned purchase, inventory, gifting and wallet rules remain. Shop dressing room checks current ownership and saves outfit/accessory per bear/cat/rabbit; passport, island SVG and cottage renderer apply the selected style. Clearing restores original looks. Lost ownership suppresses equipped items.
- Additive schema0024 creates character growth receipts, species style preferences and fireworks admission receipts. Existing migrations/tables/bindings remain unchanged; no backfill or reset. Growth receipts are inserted by triggers in the same transaction as actual collection/adventure/watering events. Stats cap each attribute at 20 XP per species per Taiwan day, level=1+floor(total/20); no decay. Reading/research earns Knowledge, exploring/picking/fishing/watering/harvest earns Adventure, stretching/snacks earns Health, sales/deliveries earns Wealth. Bread Health+2, berries Health+3, tea Knowledge+1/Health+1. Explicit daily reading/stretch forms use species-scoped expiring tokens; duplicate records add nothing. Tracking starts with V100.
- Fireworks run daily 21:00–21:10 Asia/Taipei according to server time. One ticket is consumed transactionally on first admission each evening; replay/re-entry that evening costs nothing. Unused tickets stay in inventory; yesterday's admission does not authorize today. Private scene markup is emitted only for admitted accounts during the show. Admitted island-map visitors also see the overlay. Closed waiting pages refresh at the next opening; open scenes are removed at cutoff. Reduced motion produces a still illustration. There is no real payment or external notification.
- Purchased decor can be assigned to one of four reserved display slots and a shelf/window/table/corner position, with quantity/owner validation. Existing display operations persist placement; original furniture layouts remain intact. Renderer now accepts lamp/plant/clock and draws them, along with original decor, at the selected position on a small support. These are preset positions, not arbitrary dragging; original room editor remains available. Removal returns availability to the backpack.
- Watering requests ask for a compact single-plot JSON response, update that plot plus summary, preserve measured position and keep duplicate/network retry safeguards. Successful watering no longer renders the entire page, issues unrelated tokens or initializes all plots on POST. Native non-JS forms retain their redirect flow.
